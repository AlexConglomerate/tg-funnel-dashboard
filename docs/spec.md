# Спека: мини-воронка регистраций в Telegram + дашборд в Mini App

Тестовое задание. Репозиторий `tg-funnel-dashboard`, запуск только локально.

## 1. Задача

**Из задания:**
- Бот на aiogram: `/start` → приветствие → запрос телефона → 2 сообщения по расписанию (через 10 сек и через 1 мин).
- Тексты и тайминги лежат в YAML-конфиге.
- Mini App в Telegram: простая HTML-страница со статистикой использования бота.
- Всё в одном репозитории, хостинг не нужен.
- Сдаём ссылку на репозиторий и скринкаст на 1–3 минуты.

**Акценты решения:**
1. **Пик на эфире.** На вебинаре 2000 человек одновременно идут в бот, и бот не должен ни упасть, ни потерять сообщения.
2. **Наблюдаемость.** Если что-то упало, об этом сразу приходит сообщение в Telegram, а по логам понятна причина.
3. **Контроль над ИИ.** Решение простое и обратимое, есть план, тесты и типы, а не «нагенерил и залил».
4. **Сквозная аналитика.** Видно, откуда пришёл человек и где он отвалился в воронке.

**Чего не делаем:** Postgres, Docker, миграции, вебхуки, VK/MAX, несколько инстансов. Всё это попадает в README в раздел «Что сделал бы в проде».

## 2. Стек

- Python 3.12 через `uv`. Системный Python 3.9 не используем.
- `aiogram` 3.x для бота (long polling).
- `aiohttp-socks`: необязательный SOCKS5-прокси для Bot API.
- `FastAPI` + `uvicorn` для API и раздачи статики.
- SQLite через `aiosqlite`, на чистом SQL, без ORM.
- `pydantic` + `pydantic-settings` для валидации `.env` и YAML, `PyYAML` для чтения YAML.
- Для разработки: `pytest`, `pytest-asyncio`, `httpx` (тесты API), `mypy`, `ruff`.
- `cloudflared` для временного HTTPS-туннеля к Mini App, ставится через `brew install cloudflared`.

Бот, API и планировщик работают в **одном процессе** и одном asyncio-цикле. Запуск одной командой.

## 3. Воронка (поведение бота)

### `/start [payload]`
1. **Метка источника.** `payload` из deep link (`t.me/<bot>?start=vk_ads`) записывается в `source`, если подходит под `^[A-Za-z0-9_-]{1,64}$`. Иначе ставим `direct`. Метка пишется **только при первом `/start`** (first-touch), повторные её не перезаписывают.
2. **Пользователь.** Создаём или обновляем запись (`tg_id`, `username`, `first_name`). Если пользователь был помечен как заблокировавший бота, снимаем пометку.
3. **Телефон уже есть:** отправляем `already_registered`, воронку **не перезапускаем**.
4. **Телефона нет:** отправляем `welcome`, затем `ask_phone` с reply-клавиатурой: одна кнопка `request_contact`, `one_time_keyboard`, `resize_keyboard`.

### Пришёл контакт
- **Чужой контакт** (`contact.user_id != from_user.id`): отправляем `not_own_contact` и снова показываем кнопку.
- **Телефон уже сохранён:** отправляем `already_registered`.
- **Иначе:**
  - нормализуем номер: только цифры с `+` в начале;
  - сохраняем `phone` и `phone_at`;
  - отправляем `registered` и убираем клавиатуру;
  - планируем все `followups` из конфига: `send_at = phone_at + delay_seconds`.

### Любое другое сообщение
- **Телефона ещё нет:** отправляем `use_button` и снова показываем кнопку.
- **Телефон есть:** игнорируем, только пишем в лог на уровне `debug`.

### `/dashboard` (только для `ADMIN_IDS`)
- Отвечает inline-кнопкой `web_app` на `WEBAPP_URL`.
- Если `WEBAPP_URL` не задан, пишет об этом текстом.

### Кнопка меню
При старте для каждого админа ставим через `set_chat_menu_button(chat_id=admin)` кнопку `MenuButtonWebApp("Дашборд", WEBAPP_URL)`. Обычные пользователи этой кнопки не видят.

**Отсчёт расписания идёт от момента отправки телефона, а не от `/start`.** Логика такая: регистрация завершена, дальше начинается прогрев. Кто телефон не оставил, отложенных сообщений не получает и виден на дашборде как отвал на шаге «телефон».

## 4. Конфиг `config/funnel.yaml`

Тема: регистрация на бесплатный эфир про ИИ.

```yaml
parse_mode: HTML
messages:
  welcome: "..."            # приветствие
  ask_phone: "..."          # просьба оставить номер
  phone_button: "📱 Отправить номер"
  registered: "..."         # «вы зарегистрированы»
  already_registered: "..."
  not_own_contact: "..."
  use_button: "..."         # «нажмите кнопку ниже»
followups:
  - key: gift
    delay_seconds: 10
    text: "..."
  - key: warmup
    delay_seconds: 60
    text: "..."
```

Проверка при старте через pydantic:
- все тексты непустые;
- `delay_seconds` больше 0;
- ключи `followups` уникальны и подходят под `^[a-z0-9_]+$`;
- `followups` содержит хотя бы один элемент.

Если конфиг невалиден, процесс **падает при запуске** с понятной ошибкой: путь к полю и причина. Количество отложенных сообщений не зашито в код: добавил третье в YAML, и оно работает, а на дашборде появляется новый шаг воронки.

## 5. Переменные окружения `.env`

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | токен от BotFather |
| `ADMIN_IDS` | да | Telegram ID через запятую: кто видит дашборд и получает алерты |
| `WEBAPP_URL` | нет | HTTPS-адрес Mini App, его подставляет `scripts/dev.sh` |
| `PROXY_URL` | нет | прокси для Bot API, например `socks5://127.0.0.1:1080`, если `api.telegram.org` недоступен из сети напрямую. Подключается через `AiohttpSession(proxy=...)` |
| `PROXY_SSH` | нет | `user@host` сервера с доступом к Telegram. Если задан, `scripts/dev.sh` сам поднимает `ssh -N -D 127.0.0.1:1080` и выставляет `PROXY_URL` |
| `HTTP_PORT` | нет | по умолчанию `8080` |
| `DB_PATH` | нет | по умолчанию `data/funnel.db` |
| `FUNNEL_CONFIG` | нет | по умолчанию `config/funnel.yaml` |
| `LOG_LEVEL` | нет | по умолчанию `INFO` |

`ADMIN_IDS` разбираем как строку и сами делим по запятой. JSON-разбор pydantic-settings для такой строки не подходит.

В репозиторий кладём `.env.example` без секретов. В `.gitignore` уже есть: `.env`, `.venv/`, `data/`, кэши инструментов и локальные заметки.

## 6. Данные (SQLite)

```sql
users(
  tg_id        INTEGER PRIMARY KEY,
  username     TEXT,
  first_name   TEXT,
  source       TEXT NOT NULL DEFAULT 'direct',
  phone        TEXT,
  started_at   TEXT NOT NULL,   -- первый /start, UTC ISO
  phone_at     TEXT,
  blocked_at   TEXT
)

scheduled_messages(
  id           INTEGER PRIMARY KEY,
  tg_id        INTEGER NOT NULL REFERENCES users(tg_id),
  step_key     TEXT NOT NULL,   -- key из followups
  send_at      TEXT NOT NULL,
  status       TEXT NOT NULL,   -- pending | sent | failed | blocked
  attempts     INTEGER NOT NULL DEFAULT 0,
  last_error   TEXT,
  sent_at      TEXT,
  UNIQUE(tg_id, step_key)
)
-- индекс: (status, send_at)
```

- Все времена храним в UTC. Браузер показывает их в локальном времени.
- Схема создаётся при старте (`CREATE TABLE IF NOT EXISTS`), миграций нет.
- `UNIQUE(tg_id, step_key)` + `INSERT OR IGNORE`: повторный контакт не создаёт дублей.
- Текст сообщения при отправке берётся из конфига **по `step_key`**. Правка текста в YAML действует и на уже запланированные сообщения. Если ключ из YAML удалили, сообщение получает статус `failed` с понятной ошибкой.

## 7. Планировщик отложенных сообщений

**Почему не `asyncio.sleep`:** при перезапуске процесса все запланированные сообщения терялись бы. Поэтому задачи лежат в базе.

**Цикл раз в секунду:**
- берём до 50 строк `pending` с `send_at <= now`, отсортированных по `send_at`;
- отправляем через общий **ограничитель скорости**: не больше 25 сообщений в секунду (лимит Telegram около 30 в секунду), простой token bucket.

**Исходы отправки:**

| Исход | Что делаем |
|---|---|
| успех | `sent`, `sent_at` |
| `TelegramForbiddenError` (бот заблокирован) | `blocked`; у пользователя ставим `blocked_at`; остальные его `pending` тоже переводим в `blocked` |
| `TelegramRetryAfter` | ждём `retry_after`, строка остаётся `pending`, `attempts` не увеличиваем |
| другая ошибка | `attempts += 1`, `last_error`; на 3-й попытке `failed` и алерт |

- **После перезапуска** просроченные `pending` уходят сразу: догоняем, ничего не теряем.
- **Метка работы:** планировщик записывает в память время последнего прохода цикла (`last_tick`), её использует `/health`.
- Работаем в одном процессе, блокировок между инстансами нет. В README отмечаем: при нескольких инстансах нужен Postgres и `SELECT ... FOR UPDATE SKIP LOCKED`.

## 8. API (FastAPI)

| Маршрут | Доступ | Ответ |
|---|---|---|
| `GET /` | все | `static/index.html` |
| `GET /api/stats` | админ по `initData` | JSON статистики |
| `GET /health` | все | `200 {"status":"ok", ...}` или `503`, если база недоступна или `last_tick` старше 10 секунд |

### Авторизация `/api/stats`
- Заголовок `Authorization: tma <initData>`.
- Проверка по документации Telegram:
  - `secret = HMAC_SHA256(key="WebAppData", msg=BOT_TOKEN)`;
  - строка проверки: пары `key=value`, отсортированные по ключу, без `hash`, соединённые через `\n`;
  - сравнение через `hmac.compare_digest`;
  - `auth_date` не старше 24 часов.
- Нет `initData` или подпись неверна → `401`. `user.id` не из `ADMIN_IDS` → `403`.

### JSON `/api/stats`
```json
{
  "totals":   {"started": 0, "with_phone": 0, "conversion_pct": 0.0, "blocked": 0},
  "funnel":   [{"key": "start", "label": "Нажали /start", "count": 0, "pct_of_prev": null},
               {"key": "phone", "label": "Оставили телефон", "count": 0, "pct_of_prev": 0.0},
               {"key": "gift",  "label": "Сообщение «gift»", "count": 0, "pct_of_prev": 0.0}],
  "by_source":[{"source": "direct", "started": 0, "with_phone": 0, "conversion_pct": 0.0}],
  "timeline": {"bucket": "minute", "points": [{"t": "...", "started": 0, "with_phone": 0}]},
  "queue":    {"pending": 0, "sent": 0, "failed": 0, "blocked": 0},
  "recent":   [{"name": "...", "username": "...", "source": "...", "phone_masked": "+7 *** ***-12-34",
                "started_at": "...", "phone_at": "..."}],
  "generated_at": "..."
}
```

- **Шаги воронки после «телефона»** строятся из `followups` конфига. Шаг засчитывается, когда сообщение получило статус `sent`.
- **Масштаб `timeline`:** если между первым и последним событием меньше 3 часов, группируем по минутам, иначе по часам. Так на коротком промежутке, например в первый час эфира, график не схлопывается в один столбик.
- **`recent`:** последние 10 пользователей по `started_at`. Телефон всегда в маске: видны только 4 последние цифры. Полный номер в API не уходит.

## 9. Дашборд `static/index.html`

- Один файл на чистом JS, без сборки и без библиотек графиков: столбики сделаны на CSS.
- Подключает `https://telegram.org/js/telegram-web-app.js`, вызывает `Telegram.WebApp.ready()` и `expand()`.
- Цвета берёт из темы Telegram (`var(--tg-theme-bg-color)` и т.д.): одинаково нормально выглядит в светлой и тёмной теме.
- **Блоки сверху вниз:**
  1. цифры: пришли / телефон / конверсия / заблокировали;
  2. воронка с процентами переходов;
  3. график по времени;
  4. таблица источников;
  5. очередь отправки;
  6. последние регистрации.
- Обновляется раз в 5 секунд. Показывает время последнего обновления.
- **Состояния:**
  - открыто не из Telegram (нет `initData`): «Откройте дашборд из бота командой /dashboard»;
  - `401` или `403`: «Нет доступа»;
  - сеть упала: старые данные остаются, сверху появляется плашка «нет связи».

## 10. Алерты и логи

- **Формат логов:** `время уровень модуль сообщение` в stdout, в контексте указан `tg_id`. Каждый шаг воронки пишется на уровне `INFO`: `start source=vk_ads`, `phone_saved`, `followup_sent step=gift`, `user_blocked`.
- **Ошибки обработчиков aiogram** ловит общий error handler: лог с traceback плюс алерт.
- **Алерт:** обработчик логов уровня `ERROR` отправляет сообщение всем `ADMIN_IDS`. В сообщении модуль, текст ошибки и последняя строка traceback (файл:строка).
  - Антиспам: одинаковая ошибка (тот же модуль и тип исключения) уходит не чаще раза в 60 секунд, повторы считаются: «…и ещё 37 раз».
  - Отправка алерта никогда не роняет основной поток: ошибки внутри алерта только пишутся в лог.
- **При старте** в лог пишутся версия, путь конфига, количество followups, `WEBAPP_URL` или предупреждение, что его нет.

## 11. Запуск

- `uv sync` ставит зависимости.
- **`./scripts/dev.sh`** — основной сценарий:
  1. читает `.env`;
  2. если задан `PROXY_SSH`, поднимает SOCKS-туннель (`ssh -N -D 127.0.0.1:1080`), ждёт, пока порт откроется, и выставляет `PROXY_URL`. Адрес сервера в вывод не печатается;
  3. поднимает `cloudflared tunnel --url http://localhost:$HTTP_PORT`;
  4. достаёт из его вывода адрес `https://*.trycloudflare.com`;
  5. экспортирует его как `WEBAPP_URL`;
  6. запускает `uv run python -m funnel`;
  7. при `Ctrl+C` гасит все процессы.
- **`uv run python -m funnel`** — запуск без туннеля: бот работает, кнопки дашборда нет, в логе предупреждение.
- **Проверки одной командой:** `uv run pytest && uv run mypy src && uv run ruff check`.

## 13. Тесты (pytest)

1. **Конфиг:** валидный YAML загружается; дубли ключей, `delay_seconds <= 0` и пустой текст дают ошибку.
2. **`initData`:**
   - корректная подпись принимается;
   - изменённое поле → отказ;
   - просроченный `auth_date` → отказ;
   - через API: не админ получает `403`, без заголовка `401`.
3. **Регистрация:**
   - свой контакт → телефон сохранён, создано N followups с правильными `send_at`;
   - повторный контакт не создаёт дублей;
   - чужой контакт отклонён;
   - повторный `/start` не перезаписывает `source`.
4. **Метка источника:** допустимый `payload` сохраняется, мусор превращается в `direct`.
5. **Планировщик** (с поддельным отправителем):
   - созревшее сообщение отправлено;
   - не созревшее не тронуто;
   - `Forbidden` → `blocked` для всех `pending` пользователя;
   - `RetryAfter` → остаётся `pending`;
   - 3 ошибки → `failed`.
6. **Статистика:** на заранее заполненной базе проверяем счётчики воронки, проценты и маску телефона.

## 14. README

1. Что это: 2 строки и скриншот дашборда.
2. Быстрый старт: `uv sync` → `cp .env.example .env` → `./scripts/dev.sh` → `/start` в боте → `/dashboard`.
3. Как проверить источники: ссылки `?start=vk_ads`, `?start=insta_stories`.
4. Устройство: схема в 5 строк (бот → SQLite ← планировщик; Mini App → API → SQLite).
5. Решения и почему: расписание в базе, ограничение скорости, проверка `initData`, маскировка телефонов, отсчёт от телефона, first-touch для метки.
6. Что сделал бы в проде:
   - Postgres и `SKIP LOCKED`;
   - вебхуки;
   - синтетический health-check, который каждые 30 секунд проходит воронку тестовым аккаунтом;
   - Sentry или аналог;
   - VK и MAX через адаптеры поверх `registration.py`;
   - бэкапы базы.
7. Как делалось с ИИ: спека в `docs/spec.md` → план → код в Claude Code → ревью плана и проверки.
8. Две работы с ИИ: Bany (https://bany.uk) и сервис записи кураторов для «Академии смысла».
9. Если `api.telegram.org` недоступен из сети: `PROXY_URL` или `PROXY_SSH`.
